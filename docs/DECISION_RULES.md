# 决策规则与账户事实

InvestLab 先核对账户事实，再检查风险和调整条件。每日输出一个最终结论，原有趋势模型作为参考保留。

## 判断顺序

| 条件 | 最终结论 | 适用范围 |
| --- | --- | --- |
| 行情不足、来源冲突或账户估值未核对 | 资料不足，暂停新调整 | 不生成金额、份额或新的目标仓位；已确认的市场风险仍可提示 |
| 合格行情触发长期趋势关闭或波动退出 | 减仓／退出复核 | 首先处理 TQQQ；不自动补足 QQQ 核心仓 |
| 真实估值超出用户确认的现金、资金或杠杆约束 | 降低风险复核 | 风险约束优先于配置目标 |
| 波动处于暂停新增区间 | 暂停新增 | 不等于清仓 |
| 个人资金与风险预算未确认 | 暂停新增 | 60/40 配置目标不能代替个人风险标准 |
| 条件齐备且有目标差额 | 新增复核 | 每次最多 5 个百分点，并受资金、现金和敞口限制 |
| 条件齐备且没有调整需要 | 无需调整 | 不把资料缺失写成“持有最安全” |

同一资产不会在同一轮同时得到新增与减仓建议。风险约束要求减仓时，不同时增加另一项资产以补足配置目标。所有结果都需要人工复核，系统不生成订单。

## 保留的参数

| 参数 | 定义与边界 | 状态 |
| --- | --- | --- |
| 200 日均线缓冲 | 高于 103% 开启，低于 98% 关闭；等于阈值及缓冲区内保持原状态 | 原有 C0 参数，未证明最优 |
| 20 日年化波动 | 小于 25% 才允许新增；25% 至不足 35% 暂停新增；达到 35% 退出复核 | 原有 C0 参数，非亏损上限 |
| 单步新增 | 最多总资产的 5 个百分点，且受目标差额、现金和风险约束 | 上限，不是每天配额 |
| 长期目标 | QQQ 60%、TQQQ 40% | 目标，不是成交或适配性证明 |
| RSI、20／50 日均线 | 解释市场状态 | 不新增独立买卖门槛 |

计算仍使用原有公式。没有因本轮整理而上线新的短线过滤器、周频择时或更高收益模型。固定周频复核可以后续单独研究；当前优先解决重复建议和事实缺失，避免同时修改多个条件后无法解释改进原因。

## 买入已确认、成交细节待补

现有 `ledger-import` 入口接受 `REPORTED_BUY`。它保存用户报告的日期、金额、来源和未知项，不扣现金、不补造股数、价格、费用、汇率或盈亏。只有完整成交仍使用 `BUY`。

以下全部是虚构示例：

```json
[
  {
    "event_id": "example-reported-buy",
    "account": "default",
    "occurred_at": "2026-10-01",
    "kind": "REPORTED_BUY",
    "symbol": "TQQQ",
    "currency": "CNY",
    "amount": "375",
    "amount_is_approximate": true,
    "confirmed": true,
    "evidence_level": "USER_REPORTED",
    "source": "用户原始陈述的位置",
    "note": "份额、美元成交价、费用及汇率未知"
  }
]
```

`occurred_at` 保留日期精度，不编造交易时刻。同一 ID 重复导入不累计；同一 ID 的不同内容被拒绝。记录仍使用原有的追加式 journal_events，没有建立第二份账本或新增数据库表。

之后可以导入最新完整人民币估值，并在 `reconciles_event_ids` 明确列出已核对的报告 ID。这只恢复聚合估值的可用性，不声称成交份额或历史成本已补齐。旧记录保留，不能覆盖成新的价格或成交。

## 用户风险预算

风险预算从私有 settings.json 的 risk_budget 读取，默认未确认。系统不以历史亏损或配置目标推断风险承受能力。确认项包括备用金、投资资金、可接受损失、现金要求，以及人工确认的 TQQQ 和敞口边界。数字字段以十进制字符串记录金额。

```json
{
  "confirmed": false,
  "source": "待用户明确确认",
  "confirmed_at": "YYYY-MM-DD",
  "emergency_reserve_cny": "待确认",
  "reserve_location": "OUTSIDE_ACCOUNT 或 IN_ACCOUNT",
  "investable_capital_cny": "待确认",
  "max_acceptable_loss_cny": "待确认",
  "minimum_cash_cny": "待确认",
  "maximum_daily_ndx_exposure": null,
  "maximum_tqqq_weight": null
}
```

确认后，账户内备用金与最低现金要求取较大值；可投资资金之外的账户资产也不能被自动投入。最大可接受损失用于风险情景复核，系统不承诺能把实际损失限制在该金额内。单日敞口近似不等于多日收益或亏损上限。

## 可追溯输出

- `allocation_review`：保留的 C0 模型参考，可能基于历史账户快照。
- `account_state`：当前事实的证据来源、买入报告、估值日期、未核对事件及未知项。估值不完整时，`current_values_cny` 为 null。
- `decision`：最终人工复核动作、原因、阻断项、下一次改变判断的条件及规则版本。
- `proposal_id`：由规则、账户证据、风险预算、动作及目标生成，不把运行次数或日期变化当作成交。

日报、摘要接口和原页面使用相同最终动作。读取历史报告时会重新核对当前账本，新增事实立即使旧零持仓假设失效；历史报告字节和哈希保持原样。任何执行、取消或新的账户事实都需要真实输入，日期变化不能推进仓位。

## 验证与适用边界

运行：

```bash
PYTHONPATH=src python -m unittest discover -s tests/app -q
PYTHONPATH=src:src/investlab/engine python -m unittest discover -s tests/legacy -q
python scripts/check_release.py
```

重点覆盖部分成交报告、重复导入、阈值等号、退出与新增冲突、缺失／冲突行情、风险边界、RSI反例及账户变动后旧报告失效。已有数值模型的回归与独立成交时序核验继续保留。

本轮改进的是事实完整性和决策一致性。历史已见样本、合成测试和工程运行成功不能证明未来收益改善。私有回放记录保存对照、历史反例、数据来源与局限，不把本人账户或行情原文上传公共仓库。
