# 系统架构

## 设计目标

InvestLab用Python处理行情与计算，用SQLite保存账户和报告，通过命令行与本地网页展示结果。每份报告关联计算时的代码版本和输入数据，便于核对与重现。

| 模块 | 职责 | 实现 |
| --- | --- | --- |
| 行情接入 | 获取行情，保留原始响应，检查日期、价格和来源一致性 | `providers.py` |
| 账户与记录 | 保存确认流水、估值、报告与运行状态 | `ledger.py`、`core.py`、SQLite |
| 计算引擎 | 计算指标、仓位建议、策略比较与情景结果 | `engine/`，独立子进程 |
| 数值检查 | 用独立费用算法重算净值，检查历史信号的时间顺序 | `verification.py` |
| 运行管理 | 控制写入顺序，核对保存结果，生成备份和摘要 | `service.py`、`storage.py` |
| 展示 | 查看持仓、建议、研究图表与历史记录 | `server.py`、`web/`，本机只读网页 |

## 引擎与数据目录

v6沿用v5.5的数值模块，在同一份行情上比较升级前后的结果，再为账户管理、运行和恢复模块增加独立检查。默认60/40目标、分步规则和研究参数沿用原配置。

源码与配置随Python包安装，运行数据保存在`INVESTLAB_HOME/data`。迁移后的历史源码和输入数据存放在私有目录，每份新报告保存对应代码的校验值。

## 目标、建议、估值与交易

四类记录分别保存：

- **目标**：长期期望的资产比例，默认QQQ 60%、TQQQ 40%。
- **建议**：根据最后确认持仓计算出的下一步调整参考。
- **估值**：某日已确认的各资产人民币价值。
- **流水**：已确认的入金、买卖和费用。

交易流水通过导入写入，要求`confirmed=true`、固定ID和带时区的时间。同ID内容相同按重复处理；内容冲突时整批回滚。

流水和估值采用追加记录方式。导入错误通过新增VOID记录纠正，保留原记录及原因。系统检查引用账户、币种、作废关系及纠正后的余额；出现卖出超仓或现金为负时，整批返回错误，供核对相关交易。

## 收益与币种

系统按账户和币种分别计算。已知买入成本时，计算加权平均成本和已实现损益；成本资料缺失时显示未知。这里提供投资记录计算，税务成本须按适用规则另行核算。

聚合估值适合查看资产金额。时间加权收益、内部收益率需要完整份额和资金流，多币种汇总需要同日汇率。默认监控账户以最近导入的完整估值为准，交易流水单独保存。

## 保存与运行状态

所有写操作共用一个操作系统锁。引擎生成报告后，应用按`run_id`从数据库取回并核对；完整备份通过文件清单和SQLite检查后，运行状态更新为`SUCCEEDED`。

看板从数据库读取最新报告及最近尝试的状态。发生失败或中断时，页面展示相应状态和可用的历史报告。行情时效按最新完整交易日判断，不同代码版本分别统计成功运行的交易日。

通知默认保存为本地记录，实际发送由所选调度或通知服务处理，以发送回执确认发送状态。部署时选择一套调度器，统一管理运行时间与接收渠道。
